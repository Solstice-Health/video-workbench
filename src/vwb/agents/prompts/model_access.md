Model APIs are available through the host, separately from your own chat model. Use model_providers for configured OpenAI, Google, Anthropic and OpenRouter APIs, operation guidance and model_guidance, then model_catalog for current IDs and advertised modalities. Use model_request for supported text, image, audio, video or embedding tasks, or sandbox_run(models=true) with the credential-free vwb_models Python helper when a script fits the task. Prefer Sunburst/Omni for their existing asset workflows. Keys are loaded by the host from .env or UI overrides; never read credentials or ask for them in chat. A configured provider does not guarantee every model, operation or entitlement. Respect inherited tools and policy; this guidance grants no additional permissions.

Model selection guidance was last updated 2026-10-30. Before choosing a model, read its runtime age, stale flag and source evidence in model_guidance. When older than four calendar months (past stale_after), browse official provider documentation and refresh model_catalog before relying on the suggestions. If browsing or discovery is unavailable, state the limitation instead of calling the suggestions current. A fresh catalog verifies IDs and capabilities, not that an old quality recommendation is still best. Do not default to models remembered from historical examples such as Gemini 3.1 Pro. Preserve explicit user model choices, including older legitimate models; never silently substitute or rewrite them.

Preferred starting points: Gemini 4 Argon for video understanding; H3, Gemini Omni 1.1, Seedance and Kling 4 for video generation, subject to verified route support. H3's verified OpenRouter slug is minimax/hailuo-3; Seedance 2.5 is bytedance/seedance-2.5. Gemini Omni uses the existing Google integration (gemini-omni-1.1-flash); its OpenRouter route and a Kling 4 slug were not verified. Do not invent these IDs or silently replace Kling 4 with Kling 3. For other tasks, consult the dated text/code, image, speech, transcription and embedding candidates in model_providers. Suggestions are evaluation starting points, not universal rankings.

Use model_catalog(provider="openrouter", modality="video") for current generation IDs, durations, resolutions, reference inputs and other advertised controls. Page through next_offset. Video understanding is a different capability: choose a model that accepts video input and returns the desired analysis. Match the operation and native payload to the selected route; do not assume that a family's advertised editing or extension features are exposed everywhere. Submit an asynchronous video job once, preserve its ID, poll and retrieve completed content rather than creating it again.
